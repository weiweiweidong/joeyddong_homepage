# Photography 图片加载与维护

更新日期：2026-10-14。

## 加载规则

- 列表、首屏堆叠、轮播背景、七张缩略图和前后滑动缓冲使用本网站的 WebP。列表保留原生懒加载，用真实宽高预留空间，`sizes` 对齐现有 1/2/3/4 列布局。
- 打开轮播后，当前照片先显示 640px 本地预览，仅当前照片发起一个高清加载；加载并解码成功才替换中心图片。
- 根据完整照片在浮层中实际占用的尺寸选择长边 960/1440/1920/2560px，像素比最高为 2。高清请求为 OSS 等比例缩放、`limit_1` 不放大、WebP、质量 85。没有相邻高清预加载。
- 失败时保留预览，显示三语提示、重试和原图入口。新选择或关闭会取消待处理请求并使旧回调失效。已成功加载的 URL 复用浏览器缓存，不保留全部高清图片对象。
- 原始地址仍用于“打开原图”；禁用 JavaScript 时点击图片会直接进入该地址。

## 新增与更新照片

1. 在 `src/lib/photography-sources.json` 中维护原始文件名；已有编号保持稳定，新增照片追加至末尾。
2. 执行 `npm run photography:prepare`。仅请求经过 OSS 缩小的版本，不下载完整原文件。脚本并发数为 4，生成 320/640/960px 质量 75 的 WebP，校验格式、尺寸和完整解码。请求失败会重试最多三次。
3. 生成文件位于 `public/images/photography/<编号>-<宽度>.webp`；真实宽高、字节数和来源写入 `src/lib/photography-assets.json`。图片通过校验后才原子替换，全部成功后发布清单；异常以非零退出码结束。
4. 保留生成文件及清单。重复执行复用来源和处理设置相同的有效文件，本次复跑验证为 0 次生成、234 次复用。损坏或缺失文件重新生成。普通构建和部署无需联网生成图片。

## 实测体积

单位为十进制 MB；原文件大小由 OSS 原图 HEAD 的 Content-Length 汇总，旧 640px 预览以 GET 实际响应体测量，新图大小为生成文件的真实字节数。

| 78 张照片的同一组素材 | 总量 |
| --- | ---: |
| 原始 JPEG | 116.48 MB |
| 旧 OSS 默认质量 640px WebP | 4.21 MB |
| 新本地质量 75、320px WebP | 2.06 MB |
| 新本地质量 75、640px WebP | 5.74 MB |
| 新本地质量 75、960px WebP | 10.40 MB |

640px 新图比原始文件合计少约 95.1%；每张 960px 新图也小于对应原图。三个尺寸全部文件约 18.20 MB 是仓库素材总量，访问者通过 srcset 选择其中一档，并随滚动懒加载，不会同时下载三档。

**旧页已经使用缩略图，并非自动下载全部原图。** 按已确认的质量 75 生成的新图，同尺寸下比旧 OSS 默认输出大约 36.3%。本次改善主要是把小图放到网站、消除列表 OSS 依赖，以及限制轮播高清下载与解码。上述数字不代表首次访问的总流量或实际网速提升。

当前桌面验证的轮播照片 1 使用 455×960 高清图，约 0.44 百万像素；旧版固定宽 1600px 的同图约 1600×3378，约 5.40 百万像素。仅该照片的当前显示场景，高清解码像素减少约 92%。高像素比或更大的显示空间会选择更高档位。

## 验证

- 234 个 WebP 全部完整解码、尺寸校验；第 69 张原文件名空格被正确编码，本地文件名没有空格。
- 浏览器列表所有 img/srcset 均为本地来源，轮播打开前没有启动高清请求；桌面初始加载仅覆盖附近照片，其余保持懒加载。
- 开发模式的 `[Photography HD request]` 日志验证：打开照片 1 只启动照片 1 的高清加载，切换到照片 2 才启动第二个；背景、缩略图和相邻缓冲没有 OSS 请求。日志仅存在于开发构建，用于检查新启动的高清加载，不作为网络抓包或真实流量统计。
- `npm run photography:test` 模拟慢请求、切换后的旧响应、加载失败、重试、关闭中的响应以及成功 URL 复用，并验证屏幕适配、像素比上限和 URL 空格编码。
- 三语桌面/手机页面和浮层查看器验证；保留按钮、方向键、触屏、循环、减少动态效果与 Escape 关闭。
- `npm run check`、`npm run build` 及离线素材复用检查。
